# 双 Harness 重建与比较协议

本轮目标：说明当前助手如何实现，按照原简历重建一个可运行的 LangGraph 基线，使用同一模型进行可归因的对照，从实测发现出发实现升级，形成可以在简历和面试中解释的迭代证据。

本文件是实验前协议。尚未完成的实现和结果不能当作已经验证的能力。

## 版本与历史边界

- 原简历描述：LangGraph / Graph State / Checkpoint；Dense + BM25 + Reranker；Qdrant / SQLite；FastAPI / Streamlit；论文问答、跨论文比较、源码和配置分析、训练日志、研究决策记忆、可验证引用。
- **V0 / legacy**：本轮根据上述架构从头实现的基线。原始项目代码没有提供，所以它是“按原设计重建”，不能称为找回历史代码，也不能伪造过去的研发日期和结果。
- **V1 / openharness**：上一轮已完成的应用，采用 LangGraph 外层分流 + HKUDS/OpenHarness QueryEngine 内层执行循环。上游固定 commit `9b2efd795c6aa09f88b0c257d269a9e518da6ae7`，不修改上游。
- **V2 / upgraded**：在 V0/V1 实测后，针对确定的问题加入具体改进；改进单独开关、做消融，不预先宣布一定优于基线。

LangGraph 是状态图编排框架；OpenHarness 是模型、消息和工具的运行循环。它们并非互斥方案。本次比较的主要自变量是“自写 LangGraph model↔tools 循环”与“OpenHarness QueryEngine”，保留共有的业务编排和数据层。

## 两层比较

1. **Harness 对照（主要结论）**：统一模型、Prompt、tool schema、tool handler、论文版本、检索器、引用门禁、输出上限、模型轮数、超时、采样设置和持久化条件，只替换运行循环/上下文策略。基线包含合理的 Schema 校验、错误回传、tool-call配对、checkpoint，不能故意删掉原简历已有能力。
2. **产品/检索对照（单独报告）**：重建真实 Qdrant local + 神经 dense retrieval + BM25 + cross-encoder reranking；与现有 LSA/RRF/词项重排比较检索命中与耗时。不能把检索变化、不同模型或 UI 技术变化的收益算成 harness 收益。

Streamlit 提供基线可运行入口；统一 React 界面也可选择运行版本，便于用户并排体验。共享领域工具体现控制变量，不代表基线复用了 OpenHarness 的执行循环。

基线若采用串行工具节点，测到的并行差异归因于该实现选择，不能写成“LangGraph不支持并发”。引用门禁、Web取消与SQLite/SSE若为两版共用，就应记为应用层能力，不包装为OpenHarness独有。使用同一模型时，工具选择语义能力未必因为替换框架而提升；持平或退化同样是有效结论。

## 评测设计

### 正常任务

固定论文问题、跨论文比较、未知信息拒答、源码定位、实验调用、日志诊断、保存/回读决策。主要配对组 V0/V1，每题至少3次，轮换执行顺序；短上下文先跑小样验证。

保存用户输入、完整可见回答、工具参数/结果、事件、模型请求/响应统计、引用、判据。语义质量单独复核；工程通过率不等于问答准确率。不能把AI自评称为人评金标。

### 上下文与记忆

对短会话与长会话分组，使用预先构造、明确标注为合成的历史，其中包含早期/中间/近期研究决策、后续修正、无关工具输出。值使用随机标识，避免从模型常识猜中。

基线先使用全历史保留，与原简历checkpoint的合理默认一致。可加“按完整消息轮次滑窗”作为单独消融，不能将最差截断法冒充唯一的LangGraph能力。

OpenHarness 实际策略包含 microcompact、context collapse、session-memory condensation、LLM summary，并非每次都做模型摘要。显式设置压力测试阈值，记录实际触发哪个分支、前后消息数/长度、配对完整性、关键事实保留、总费用相关token（含压缩调用）和后续多轮摊销。缩小阈值只是可复現压力条件，不冒充触及模型真实上下文上限。

不只看压缩率：需同时看遗漏/旧决策覆盖、最新决策准确率、重新检索次数、峰值请求长度、总输入/输出token。

### 工具和故障

自然模型调用：工具选择、参数合法率、有效结果率、引用回溯、错误后的修正轮数。

确定性故障注入独立为 mock/fault-injection 组：非法Schema、未知工具、工具抛异常、并行一项失败、429/超时、空响应、轮数上限、重复写副作用、工具消息缺失、取消和进程恢复。共享传输重试与框架原生恢复要分别归因；模拟工具延迟不当作真实模型加速。

### 指标

- 任务完成、引用存在与当前轮读取、所需论文覆盖、事实/数值检查。
- 每任务工具调用数、错误率、修复轮次、消息配对完整率。
- 输入/输出/缓存/reasoning token、API请求数、压缩请求数与token。
- 首个可见token、总耗时、工具执行耗时、p50/p95（小样本注明不稳定）。
- 上下文峰值/压缩后长度、关键事实与修正保留率、后续多轮累计token。
- 并发、取消/恢复等机制与维护复杂度。代码行数可描述实现规模，不能当质量分。

实际账单单价未提供时不编造人民币金额，报告token及公式。计数来自供应商usage，缺失必须标未知，不能显示成0。上游OpenAI适配器对有工具的请求会去掉stream_options，且QueryEngine用量不包含某些压缩调用；对照需要共有的透明观测层统计所有实际调用，保留原生统计作对比，不修改上游。

## 首轮运行后的判据校正（保留原结果）

- digits 回答可能使用 `0.9778`，也可能使用 `97.78%`。初版脚本只检查百分数字符串，会错误判失败。最终统计在同一份原始回答上同时接受四位小数和两位百分数，保留 `raw_checks` 与修订判据；不重跑挑选回答。
- 拒答的“无法根据这四篇论文确认”没有命中初版“无法确认”连续词正则。增加相同含义的语序匹配，保留原判据与修订原因；这只纠正拒答标记，不说明回答附带的论文结论都正确。
- 代码出现当前轮已读取函数的合法子范围时，旧应用门禁仍按其原本规则记为失败。V2 在独立校验层支持子范围和单行引用，另以原回答回放做消融；超范围及未读取的引用必须拒绝。
- 部分 LLM 摘要触发25秒超时而未收到 usage。该次真实计费未知，不能把已收到 usage 的小计当总用量；报告同时列已观测 token 小计和 usage 完整性。新统计字段在缺失时将总用量置空，旧 trace 可从每次 `calls[].usage` 重算。
- 单次短历史回忆也可能出现模型输出波动。所有重复运行均保留，不因温度为0就假定完全确定。
- 语义复核取每个正常任务、每个版本的第1次重复，共30条，匿名提供输入/回答/工具返回，同模型按完整rubric评分。它不是人评金标，也不是独立模型评价。另保留主执行AI对失败/误判边界样本的定向证据回查；发现的问题不反向修改原匿名评分。
- 早期trace每轮的compact_metadata共享同一可变对象，因此压缩分支统计只读取最后一轮的累计列表一次。逐轮时点以不可变事件或API请求为准，不从此字段编造分轮压缩次数。
