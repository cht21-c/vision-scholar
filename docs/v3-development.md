# V3 开发记录与实验口径

这份记录保留开发阶段的失败。开发集用于发现和修正问题，不能作为独立泛化成绩。留出集成绩另列。

## 可独立说明的工程贡献

| 模块 | 本项目设计与实现 | 复用部分 | 验证方式 |
|---|---|---|---|
| ResearchEngine | 独立模型/工具循环、取消传播、请求视图组装 | OpenHarness 消息、事件、工具接口 DTO；共享模型传输 | 工程回归、真实模型、同工具对比 |
| 预算上下文 | 保留完整历史，按完整用户轮选择；超预算才外置大结果；逐轮给出取舍与哈希 | V2 的用户原句决策账本 | 全历史/预算消融、随机标识留出题 |
| 工具调度 | 连续只读调用限流并行，写操作前后设屏障；逐 call ID 记录真实执行区间 | 工具的 read-only 声明 | 同一调用清单在串行/直接并行/屏障模式回放 |
| 工件证据 | 会话范围的内容寻址结果、哈希校验、可分页/按词重读 | SHA256、文件原子替换等通用方法 | 篡改、跨会话、预算和消息配对测试 |
| 研究闭环 | 不可变方案、进程执行、DB 抢占、同方案复用、逐样本证据、UI | sklearn digits、PCA、SVM、bootstrap 等标准算法 | 真数据运行、独立指标重算、浏览器演示 |
| 方案短引用 | 本轮短引用精确映射完整方案哈希，减少模型长 ID 抄写错误 | 普通字典映射 | 开发失败→修复、未注册引用拒绝、跨 run 失效测试 |

“原创”指本项目独立完成的工程设计与实现，不代表算法首创、专利新颖性、或完全没有复用开源。V3 不继承或调用 QueryEngine/LegacyEngine 的执行循环；V0/V1/V2 仍保留作对照。

## 冻结顺序

- `benchmarks/v3/protocol.json` 在 V3 实现前固定：真实任务完整 Prompt、开发/留出划分、种子、研究参数、调度场景和工程判据。SHA 记录在同目录 `freeze.json`。
- 合成上下文的**完整生成器实现**是在开发阶段完成的，其源码与留出样本 hash 在 `implementation-freeze.json` 固定。因此不能声称完整上下文生成器也在实现前完成了预注册。
- `implementation-freeze.json` 固定开发完成后、运行留出集前的后端和评测源码。开发快照保存在本地 `data/snapshots/v3-before-heldout/`。
- 留出任务是项目自建的程序化/真实工具任务，不是外部公开 benchmark 或人评金标；程序化上下文与开发题共享生成机制，只更换预留种子。
- 如查看留出失败后改变行为策略，旧批次转为开发证据，另外冻结新批次。

## 开发失败与修复

1. **长哈希被抄错**：最初 V3 真实研究题反复把 64 位方案 ID 抄短，10 轮内没有执行成功。原始失败保存在 `tasks-dev-dev-study-research-r1.json`。修复提供 `study-1` 形式的本轮短引用；后端只做精确映射，拒绝猜测、模糊修复和跨 run 使用。完整哈希仍绑定方案和公开证据。
2. **评测格式误判**：最初 V2 研究题把准确率写为 `0.9815` 而非 `98.15%`，旧检查器判错。修订检查器同时接受百分比两位小数、比例四位小数；原判分与原 trace 保留，不覆盖历史文件。该检查器只检查数值出现，不证明表格对应关系与全部语义正确，另需语义复核。
3. **过早外置证据**：初版预算策略对任何大于阈值的工具结果都生成工件，短对话也会引入额外重读和抄写错误。改为完整请求已经放得下时保留原样；只有超预算才外置结果并选择历史。开发重测体现了问题减少，但单次开发题不当作统计收益估计。

开发批次均逐题原子保存，包括错误、工具输入输出、模型请求和全部可观测 usage。缺失 usage 不记作零。`data/v3/tasks-dev*` 保存三个批次；最终 b3 为 V2/V3 各四题，合计 **8/8** 通过预设工程判据。

## 当前验证

- 84 项工程测试通过；其中包含既有 59 项回归，以及独立循环、并发/取消、工件、方案与真实研究新增测试。
- 前端 TypeScript 与生产构建通过；构建仍提示较大的 JS bundle，尚未做页面拆包。
- 开发上下文 12 个真实模型试验均满足标识核对；其中包含全历史、V2 与 V3 预算视图，不能作为留出成绩。
- 调度三模式各 40 次回放：串行 40/40，直接并行 35/40，读并行/写屏障 40/40。直接并行在 write→read 场景五次均读到旧值；其他场景可能因执行时序偶然满足语义。延迟为人工注入，只用于说明机制。
- 真实研究采用种子 17/43/89，60/20/20 分割，PCA 24 维，候选 C=0.1/1/10，高斯噪声 σ=3、2×2 随机遮挡；模型与变换只拟合训练集，C 仅按 clean 验证集选取。
- 两种模型的 clean 平均准确率约 98.15%，但噪声条件下均接近随机分类水平。这是需要报告的鲁棒性失败，不能挑选 clean 指标声称模型总体表现优秀。具体数值、区间和证据以最终实测报告为准。

## 可复验入口

```bash
# 不需要模型 API；运行固定真实研究
python -m scripts.reproduce_study

# 将输出的 evidence_directory 传入，独立重算指标与区间
python -m scripts.verify_study <evidence_directory>

# 工程回归
python -m pytest -q

# 调度消融（人工延迟）
python -m scripts.benchmark_scheduler
```

字符预算衡量的是包含系统 Prompt、工具 Schema 和消息的 canonical DTO JSON 字符数，不是供应商真实 token 或网络请求字节上限。必要内容超预算会明确失败。工具只读声明不做静态副作用证明；同步线程型领域工具取消后可能仍完成已开始的操作，不提供任意副作用 exactly-once 保证。研究子进程可以被终止，但不实现进程崩溃后的断点续训。
